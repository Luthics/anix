# OS Agent（POSIX 原生 Agent 运行时）v1.0 技术规范

**版本**：v1.0.0-rfc  
**状态**：Normative Specification（RFC 级实现规范）  
**协议版本**：`ir_version = 1`  
**目标平台**：Linux (x86\_64 / arm64)、macOS (Apple Silicon / Intel)、WSL2  
**参考实现语言**：Rust（多个独立静态编译二进制，零外部运行时依赖）

## 1\. 设计哲学与规范性约定

### 1.1 规范性关键词（RFC 2119）

本文档中的关键词 **必须（MUST）**、**严禁（MUST NOT）**、**应当（SHOULD）**、**可以（MAY）** 均按 RFC 2119 解释。凡标注“必须/严禁”的条款，参考实现与兼容实现均不得偏离。

### 1.2 核心定位

本项目将传统应用层 Agent Harness 溶解进 POSIX 操作系统：

* **Agent 即标准 POSIX 进程**：每个 `*.agent` 文件通过 Shebang 直接执行，与 `grep`、`awk`、`jq` 享有同等进程语义。  
* **最小内核原则**：核心二进制 `agent` 仅负责协议解析、FD 路由、推理循环调度、上下文状态机与信号处理；严禁在 `agent` 内置特定 LLM SDK 或文件系统虚拟化层（如 OverlayFS）。  
* **确定性边界包裹概率性内核**：除模型推理本身外，所有 I/O 通道、FD 编号、线协议 Schema、错误码、超时与权限门禁均必须遵循确定性行为（Fail-Fast / Fail-Closed）。

## 2\. 系统组件总览

v1.0 核心发行包采用多个独立静态二进制按 POSIX/FHS 惯例分层安装，严禁将内部辅助程序塞入用户全局 `$PATH`（仅 `agent` 进入 `~/.local/bin/`）：

| 组件 | 角色定位 | 默认安装路径 | 核心职责 |
| :---- | :---- | :---- | :---- |
| **`agent`** | 核心解释器（必需） | `~/.local/bin/agent` | 解析 `*.agent` 与 CLI/配置、管理多路 FD 与三流输出、维护 WAL 上下文与 Prefix-Cache 约束、驱动推理循环与外部 Provider/Hooks。 |
| **`msh`** | Model-oriented Shell（必需） | `~/.local/libexec/agent/msh` | 面向模型的非交互 Shell 包装器。执行 ANSI 清洗、超长输出折叠、二进制熔断、防挂起注入，并向子进程挂载 `$AGENT_OUT` / `$AGENT_ERR` / `$AGENT_CTL`。 |
| **`agent-provider-openai-responses`** | 默认 Provider 驱动（必需） | `~/.local/libexec/agent/agent-provider-openai-responses` | 实现 Canonical IR（`ir_version = 1`）与 OpenAI Responses API（及兼容端点）之间的无状态双向协议转换。 |
| **`a* 工具集（aview、aclr）`** | 显式模型增强工具（必需） | `~/.local/libexec/agent/tools/` | 严禁覆盖原生命令（`cat`/`ls`）。通过 `$AGENT_CTL` 侧信道与 `agent` 通信：`aview` 负责显式多模态输入，`aclr` 负责显式全量/尾部上下文折叠。 |

* **私有组件解析顺序**：`agent` 解析 `shell`（默认 `msh`）与 Provider `bin` 时，若配置值为包含 `/` 的路径则直接执行；否则按 用户 `$PATH` → `~/.local/libexec/agent/` 顺序查找（既保持默认环境干净，又允许用户在 `$PATH` 中覆写自定义实现）。  
* **msh 默认 PATH 注入**：`agent` 拉起 `msh` 时，必须自动将 `~/.local/libexec/agent/tools/` 前置（prepend）到子进程 `PATH` 中，使 `aview`、`aclr` 等 `a*` 工具在 `msh` 内开箱即用，而绝不污染人类终端的全局 `$PATH`。

## 3\. CLI 接口与 `*.agent` 文件规范

### 3.1 CLI 调用语法

```sh
agent [OPTIONS] <SCRIPT.agent> [--] [<SCRIPT_ARGS>...]
agent trust <PATH>          # 信任项目级 hooks/ 并记录 SHA-256
agent --doctor              # 校验环境、权限与默认 Provider 连通性
agent --version             # 输出版本号与支持的 ir_version
```

`--` 可选，仅在传递以 **\-** 开头的裸参数且不希望被 `agent` 解析为自身选项时用于分隔。  
核心 CLI 选项（优先级最高）：

* `-c, --context &lt;FILE&gt;`：指定持久化 WAL JSONL 文件路径；传空串 `""` 强制无状态。  
* `--provider &lt;NAME&gt;` / `--model &lt;ID&gt;` / `--shell &lt;PATH&gt;`  
* `--max-turns <N> / --max-tokens <N> / --max-output-tokens <N> / --compact-threshold <VAL> / --no-compact`  
* `--approval &lt;ask|auto|deny&gt;` / `-y, --yes`（等价于 `--approval auto`）  
* `--param <KEY=VALUE>`：透传给 Provider 的额外模型参数（可重复指定；值优先按 JSON 字面量解析，否则作为字符串）。  
* `--stderr &lt;auto|explicit&gt;` / `-q, --quiet`（等价于 `--stderr explicit`）  
* `--inbox <DIR>`：进入常驻 Inbox 队列消费模式（Maildir 风格原子目录队列，异步非阻塞接收多 Agent 或外部消息）。  
* `--idle-timeout <SEC>`：常驻模式下的闲置自动退出秒数（默认 `300`；设为 `0` 表示永不因闲置退出，直至收到 `SIGINT`/`SIGTERM`）。

### 3.2 `*.agent` 文件格式与解析规则

1. **编码与行尾**：文件必须为合法 UTF-8；解析器必须同时兼容 `\n` 与 `\r\n`。  
2. **Shebang**：若首行以 `#!` 开头，解析器必须忽略该行。  
3. **YAML Frontmatter**：Shebang 之后（或文件首行）若出现独占一行的 `---`，则至下一个独占一行的 `---` 之间的内容作为 YAML 1.2 Frontmatter 解析；其余文本（去除首尾空行）作为 `agent_prompt`。若无 `---` 块，则全文作为 `agent_prompt`。  
4. **未知字段处理（Fail-Closed）**：Frontmatter 中出现未定义字段（除 `x-*` 扩展命名空间外）时，`agent` 必须向 `fd 2` 报错并以退出码 `2` 退出。

示例：

```
#!/usr/bin/env agent
---
name: security-auditor
provider: openai-responses
model: deepseek-v4.1-flash
shell: msh
max_turns: 15
max_tokens: 128000
compact_threshold: 0.8
approval: ask
stderr: auto
---
你是一个安全审计专家。读取传入的代码变更，分析潜在的并发竞态、注入与越权漏洞，输出高危漏洞的 JSON 数组。
```

### 3.3 Frontmatter 字段定义

| 字段 | 类型 | 默认值 | 确定性约束 |
| :---- | :---- | :---- | :---- |
| `name` | string | 文件名（去后缀） | 仅允许 `[a-zA-Z0-9._-]`；用于 Trace 与日志标识。 |
| `provider` | string | 全局 `defaults.provider` | 必须匹配 `config.toml` 中已定义的 `[providers.<name>]`。 |
| `model` | string | 全局 `defaults.model` | 非空字符串，透传给 Provider 驱动。 |
| `shell` | string | `"msh"` | 可执行文件路径或 `$PATH` 中的命令名。 |
| `max_turns` | uint32 | `20` | 必须 `>= 1`；达到上限且任务未完成时以退出码 `124` 退出。 |
| `max_tokens` | uint32 | `128000` | 必须 `>= 1024`；上下文硬上限，超出且无法压缩时以退出码 `124` 退出。 |
| `max_output_tokens` | uint32 | `0`（由上游决定） | 为 0 或省略时不写入 IR，沿用上游模型默认上限；若显式设为 \>= 1，则必须 \< max\_tokens，且写入 IR header.max\_output\_tokens，Provider 必须将其映射至上游输出 Token 上限参数。 |
| `compact_threshold` | float \| uint32 | `0.8` | 若为 `(0.0, 1.0)` 浮点数，表示 `floor(max_tokens * val)`；若为 `>= 1` 整数，表示绝对 Token 数；若为 `0` 或 `>= max_tokens` 或传入 `--no-compact`，则禁用自动压缩。 |
| `approval` | enum | `"ask"` | 仅允许 `ask` \| `auto` \| `deny`。 |
| `stderr` | enum | `"auto"` | 仅允许 `auto` \| `explicit`。 |
| `context` | string | `""`（无状态） | 相对路径按当前工作目录（cwd）解析；为空时严格无状态。 |
| `params` | object | `{}` | 开放键值对透传字典（内部键不受未知字段 Fail-Closed 限制）；内核不解析其业务语义，按优先级浅合并后原样透传至 IR header.params 交由 Provider 处理。 |

### 3.4 配置优先级与环境变量继承

配置合并严格遵循以下优先级（高覆盖低）：  
`CLI 参数 > 环境变量 > *.agent Frontmatter > 项目 .agent/config.toml > 全局 config.toml > 内置默认值`  
标准环境变量映射：

* `AGENT_PROVIDER`、`AGENT_MODEL`、`AGENT_SHELL`、`AGENT_MAX_TURNS`、`AGENT_MAX_TOKENS`、`AGENT_MAX_OUTPUT_TOKENS`、`AGENT_COMPACT_THRESHOLD`、`AGENT_APPROVAL`、`AGENT_YES`（`1`/`true` 等价于 `--approval auto`）、`AGENT_STDERR`、`AGENT_LOG`（`human`\|`info`\|`trace`）、`AGENT_CONTEXT`、`AGENT_INBOX`、`AGENT_IDLE_TIMEOUT`。  
* **空串覆盖规则**：`AGENT_CONTEXT=""`（已设置但为空）必须覆盖 Frontmatter 中的 `context`，强制本次运行无状态。  
* **子进程隔离规则**：`agent` 拉起 `msh` 前必须显式 `unset AGENT_CONTEXT`，防止父子 Agent 共享同一 WAL 文件导致状态污染或锁冲突；其余 `AGENT_*` 变量默认向下继承。  
* **params 浅合并规则**：params 字典按 CLI \--param \> \*.agent Frontmatter params \> 项目/全局 config.toml \[providers.\<name\>.params\] 的优先级执行键级浅合并（Shallow Merge），高优先级仅覆盖同名键，不整体清空低优先级字典。

## 4\. I/O 协议与全局文件描述符（FD）分配表

为彻底消除多路输入、Trace 输出与内部侧信道之间的 FD 冲突，本规范将**外部 `agent` 进程**与**内部 `msh` 子进程**的 FD 空间严格隔离并固定编号。

### 4.1 外部 `agent` 进程 FD 契约

* 

| FD | 方向 | 角色 | 确定性行为规范 |
| :---- | :---- | :---- | :---- |
| **`fd 0`** | R | 主输入（stdin） | 阻塞读取全部字节直至 EOF（默认不支持流式边读边推）。若 CLI 传入了 `<SCRIPT_ARGS>`，将其按空格拼接并包装为 `<args>...</args>` 置于 `fd 0` 内容之前作为首条 `turn_user` 文本；当 `isatty(0)` 为真且已传入 `<SCRIPT_ARGS>` 时，**严禁阻塞等待 `stdin` EOF**，直接以 `<SCRIPT_ARGS>` 作为用户输入启动推理；仅当 `isatty(0)` 为真且未传入任何 `<SCRIPT_ARGS>` 时，阻塞读取 `stdin` 至 Ctrl+D（EOF）。 |
| **`fd 1`** | W | 纯净 Payload（stdout） | **无论 `isatty(1)` 真假，严禁写入模型普通文本或日志**。仅转发子进程显式写入 `$AGENT_OUT` 的原始字节流。 |
| **`fd 2`** | W | 人类诊断流（stderr） | `auto` 模式：接收模型普通文本、思考摘要、工具执行状态、`$AGENT_ERR` 写入内容及致命错误；`isatty(2)` 为真时以 ANSI Dim（`\x1b[2m`）降噪渲染。任务结束前向 `fd 2` 输出一行静态 ANSI Dim 汇总（严禁使用光标回退或动态刷新），包含当前上下文水位 `ctx &lt;cur&gt;/&lt;max&gt; (&lt;pct&gt;%)`、本次运行累计消耗 `run`（含内置压缩器开销，非零细项如 `cached`/`write`/`reasoning` 按需展示），以及 `-c` 持久化会话下的跨压缩总消耗 `total`。`explicit` 模式（含 `-q`）：仅输出 `$AGENT_ERR` 写入内容及运行时致命错误；普通文本与思考仅落 `fd 3` Trace；严禁向 `fd 2` 输出 `[usage]` 汇总行（仍落 `fd 3` Trace 与 `on-exit.d/`）。 |
| **`fd 3`** | W（可选） | 结构化 Trace（JSONL） | 启动时通过 `fcntl(3, F_GETFL)` 探测：若 `fd 3` 已打开且可写（`O_WRONLY`/`O_RDWR`），则每条事件以单行 JSONL 写入 `fd 3`；否则尝试连接 `$XDG_RUNTIME_DIR/agent/journal.sock`（Linux 回退 `/tmp/agent-<uid>/journal.sock`）；若 Socket 不存在则静默丢弃（非致命）。 |
| **`fd 4..=9`** | R（可选） | 静态多路输入 | 启动时按序探测 `fd 4` 至 `fd 9`：凡处于打开且可读状态（`O_RDONLY`/`O_RDWR`）的 FD，阻塞读取至 EOF，按编号顺序包装为 `<input fd="N">...</input>` 附加在 `fd 0` 内容之后。 |

**FD 清理铁律**：`agent` 在读取完 `fd 4..=9` 后必须立即关闭这些描述符，并在 `spawn` 任何子进程（`msh`、Provider、Hooks）前确保除明确约定通道外的所有内部 FD 均设置 `FD_CLOEXEC`。  
静态多路输入示例（注意避开保留给 Trace 的 `fd 3`）：

* 

```sh
git diff HEAD~1 | ./audit.agent 3> audit.trace.jsonl 4< error.log | jq '.[] | select(.severity=="high")'
```

### 4.2 常驻队列与 Inbox 投递模式（`--inbox` / `--idle-timeout`）

普通调用（未传 `--inbox`）完成单次任务后必须立即退出 `0` 并关闭 `fd 1` EOF，以保证标准 Shell 管道不阻塞。当指定 `--inbox <DIR>` 时，`agent` 进入常驻事件循环模式，采用 POSIX Maildir 风格目录队列实现多 Agent 间异步、无阻塞、不交错的消息投递：

5. **1\. 目录结构初始化**：启动时若 `<DIR>` 或其子目录 `tmp/`、`new/`、`cur/`、`done/` 不存在，必须以权限 `0700` 自动创建。  
6. **2\. 非阻塞原子投递契约（发送方）**：发送方（其他 Agent 或外部脚本）向 `<DIR>` 发送消息时，必须先将完整内容写入 `<DIR>/tmp/<ts_ns>-<pid>-<rand>`，关闭文件后通过原子 `rename()` 移入 `<DIR>/new/`。该机制保证发送方永不阻塞（无论接收方是否在线或正忙），且彻底杜绝多写者大消息字节交错。  
7. **3\. 串行安全消费（接收方）**：`agent` 通过 `inotify`/`kqueue`（不支持时回退 200ms 轮询）监听 `<DIR>/new/`，按文件名 ASCII 字典序逐条串行消费：  
   * 仅在当前推理任务结束、所有 `tool_calls` 闭合的安全边界取出下一条消息，严禁并发修改上下文。  
   * 消费前先将 `new/<name>` 原子 `rename()` 至 `cur/<name>`，读取全部字节并包装为 `<input source="<name>">...</input>` 作为新的 `role: "user"` 消息触发推理。  
   * 该次任务完成并提交 WAL 后，将 `cur/<name>` 移至 `done/<name>`。  
8. **4\. 保持模式与闲置退出（`--idle-timeout <SEC>`）**：  
   * 启用 `--inbox <DIR>` 后，`agent` 在完成初始输入（如有）或某条 Inbox 消息后不退出，保持进程在线并持续持有 `-c <file>` 的 `flock` 独占锁，以最大化复用服务端 Prompt Cache。  
   * 自最后一次任务完成起，若连续 `<SEC>` 秒（默认 `300` 秒）内 `new/` 无新消息到达，则自动优雅退出（退出码 `0`）并释放 `flock`；若设为 `0`，则永不因闲置退出，直至收到 `SIGINT` 或 `SIGTERM`。

### 4.3 内部 `msh` 子进程 FD 契约与防截断机制

`agent` 每次执行工具调用拉起 `msh` 时，必须按以下固定映射构造子进程 FD：

* 

| 子进程 FD | 环境变量 | 底层实现与确定性语义 |
| :---- | :---- | :---- |
| **`fd 0`** | \- | 绑定 `/dev/null`（严禁继承外部 stdin，彻底杜绝交互挂起）。 |
| **`fd 1, fd 2`** | \- | 绑定至 `msh` 内部捕获管道，经 ANSI 清洗、超长折叠与二进制熔断后作为工具结果返回模型。 |
| **`fd 4`** | `AGENT_OUT=/dev/fd/4` | **匿名 `pipe()` 写端**。主进程后台协程将读端原样字节流转发至外部 `agent` 的 `fd 1`。 |
| **`fd 5`** | `AGENT_ERR=/dev/fd/5` | **匿名 `pipe()` 写端**。主进程后台协程将读端原样字节流转发至外部 `agent` 的 `fd 2`（`auto` 与 `explicit` 模式均始终可用）。 |
| **`fd 6`** | `AGENT_CTL=/dev/fd/6` | **统一侧信道控制管道（匿名 `pipe()` 写端）**。供 `aview`、`aclr` 等 `a*` 工具向主进程发送单行 JSONL 控制帧（格式见第 7.2 节）。 |

**规避 `O_TRUNC` 截断陷阱**：严禁通过 `dup2` 将外部 `fd 1`/`fd 2` 直接暴露给子进程。经由匿名 `pipe()` 中转后，POSIX 内核对管道文件自动忽略 `O_TRUNC`，确保即使外部重定向至普通文件（`./audit.agent > out.json`）且模型多次执行 `> $AGENT_OUT`，所有写入均安全顺序追加，永不互相覆盖。

### 4.4 运行时动态契约注入（`00-posix-runtime`）

`00-posix-runtime` 的默认逻辑必须内置于 `agent` 二进制中（无需依赖磁盘预置文件，确保全新环境与 `cargo test` 开箱即用）；仅当全局或已信任的项目 `hooks/pre-context.d/` 中存在同名文件 `00-posix-runtime`（或 0 字节文件 / 指向 `/dev/null` 的软链）时，按第 8.3 节规则被外部覆盖或屏蔽。用户编写 `*.agent` 时无需提及 `$AGENT_OUT`/`$AGENT_ERR`。内置默认钩子 `00-posix-runtime` 必须在首轮组装 `system_context` 时按当前 `stderr` 模式确定性注入契约：

* **`stderr = auto`**：声明普通回复展示于 `stderr`，最终交付数据必须通过 `msh` 重定向至 `$AGENT_OUT`，可使用 `$AGENT_ERR` 在命令执行时顺手向人类汇报状态，可使用 `aview` / `aclr`。  
* **`stderr = explicit`**：声明普通回复仅为内心独白、对人类完全不可见；面向人类的任何提示或警告必须显式写入 `$AGENT_ERR`，最终交付数据必须写入 `$AGENT_OUT`。

## 5\. 人类交互审批与 Fail-Closed 门禁

所有人工审批严禁读写 `fd 0`，必须直接以 `O_RDWR` 打开控制终端 `/dev/tty`。

### 5.1 审批触发规则

* **`approval = auto`**（或 `-y` / `AGENT_YES=1`）：直接放行所有 `msh` 工具调用。  
* **`approval = deny`**：严禁执行任何不在 `config.toml[approval].safe_commands` 白名单中的命令；命中拦截时向模型返回 `"Error: Command denied by approval=deny policy"`（或按 `--fail-on-deny` 退出 `42`）。  
* **`approval = ask`**：每次调用 `msh` 前检查命令首词是否命中 `[approval].safe_commands`（只读安全命令白名单）或本次进程内存中的 `Always` 放行表；未命中则触发 `/dev/tty` 审批。

### 5.2 `/dev/tty` 交互协议：`[y/n/a/e]`

向 `/dev/tty` 打印待执行完整命令并读取单字符指令：

* **`y` (Yes)**：放行本次执行。  
* **`n` (No)**：不终止进程；允许用户输入可选拒绝理由，并将 `"Error: User denied this action. Reason: <reason>"` 作为工具执行结果返回模型。  
* **`a` (Always)**：将当前命令的**可执行程序名（argv\[0\]）**加入当前 PID 生命周期的内存白名单（不持久化落盘），本次运行内同类命令自动放行。  
* **`e` (Edit)**：将待执行命令写入 `/tmp/agent_edit_<uuid>.sh`（权限 `0600`），调用 `$EDITOR`（回退 `vi`）编辑；退出码为 `0` 且内容非空时执行修改后的命令，随后删除临时文件。

### 5.3 非交互环境降级（Fail-Closed）

当 `approval = ask`、未开启 `-y`/`AGENT_YES=1` 且无法打开 `/dev/tty`（如 cron、CI/CD、无 TTY 管道）时，一旦触发需审批命令，**严禁阻塞等待**，必须立即向 `fd 2` 打印被拦截命令并以退出码 **`42`** 终止进程。

## 6\. 上下文管理、WAL 持久化、信号与退出码

### 6.1 自动上下文压缩、硬上限熔断与 `aclr`

**1\. Turn ID 锚点规则**：每个会话（或单次无状态运行）维护严格单调递增的整数 `turn_id`（从 `1` 开始，每次用户消息入队或工具执行结果返回均递增 `1`，即使发生 `fold` 也不回退编号）。`msh` 自身不感知 `turn_id`，仅返回清洗后的文本与子命令退出码；`[t<turn_id>] exit=<code>\n` 头部锚点统一由主进程 `agent` 在构造 `turn_tool.text` 时拼接。

* **2\. 每轮推理前预算检查（计算当前有效上下文水位 T\_cur）**：  
  * 定位当前活跃窗口内**最后一条存活的 `role: "assistant"` 消息**：若存在且携带 `usage`，则以该条 `usage.input_tokens + usage.output_tokens` 为基准，加上其后所有活跃消息的保守字节估算 `ceil(bytes / 3)`。  
  * 若活跃窗口内无带 `usage` 的存活 `assistant`（如首轮，或刚完成大压缩 `checkpoint` 仅剩新冻结 `system` 与 `<checkpoint>` 摘要），则对整个活跃窗口统一执行 `ceil(bytes / 3)` 估算；**严禁**将大压缩内置压缩器的 `usage` 计入新窗口 `T_cur`（防止推理模型的 `reasoning_tokens` 导致水位严重高估）。  
  * 发生小压缩（`aclr -t` 尾部折叠）后，尾部轮次被弹栈，最后一条存活 `assistant` 自动回退至折叠边界之前，`T_cur` 同步回落。  
  * 若压缩后（或禁用自动压缩时）仍有 T\_cur \> max\_tokens，必须立即向 `fd 2` 输出超限错误并以退出码 **`124`** 熔断退出。

**3\. 显式折叠原语 `aclr`：**

* `aclr -s`：触发全量自动压缩（按第 4 条 `[compact]` 策略生成结构化摘要、写入 `checkpoint`，并重新执行 `pre-context.d/` 刷新冻结 `system_context`）。  
  * `aclr -t <N> "<summary>"`：直接尾部折叠（零额外 LLM 调用）。校验 `N > last_checkpoint_turn && N <= current_turn`；非法则返回退出码 `2` 且不修改上下文。合法时将 `turn N ..= current_turn`（**连同触发本次 `aclr` 的当前轮 `assistant(tool_call)`**）原子弹栈，原位压入 `&lt;folded turns="N..now"&gt;summary&lt;/folded&gt;`，**严禁修改头部 `system_context` 与 `1..N-1`**，最大化保留 Prefix-Cache。  
  * `aclr -t <N>`（无摘要参数）：`[TODO v1.1]` 自动调用 LLM 总结 `N..now`；v1.0 中调用此形式必须返回退出码 `2` 并提示传入摘要字符串。  
  * 无参调用 `aclr`：严禁清空上下文；必须返回退出码 `2` 并打印 usage（人类彻底重置会话直接 `rm &lt;ctx.jsonl&gt;`）。  
  * **工具对闭合对齐（Tool-Pair Closure）**：若传入的 `N` 落在某条 `role: "tool"` 消息上（例如模型依据工具输出锚点 `[t3]` 调用 `aclr -t 3 "..."`，而其配对的 `assistant(tool_call)` 位于 `t2`），运行时必须自动将 `from_turn` 向上对齐至对应 `assistant(tool_call)` 的 `turn_id`（即对齐为 `t2`），将该 `assistant` 及其同批所有 `tool` 消息一并纳入折叠范围，严禁产生违反第 9.1 节不变量 (2) 的孤立 `tool_calls`。  
* **4\. 可覆写的压缩策略（机制与策略分离）**：自动压缩、`aclr -s` 与 `SIGUSR1` 均严禁写死单一模型或提示词，必须按以下确定性优先级解析 `[compact]` 配置：  
  * **外部自定义压缩器（`[compact].bin` 非空，最高优先）**：`agent` 将当前 Canonical IR JSONL 写入该可执行文件的 `stdin` 并关闭写端，读取其 `stdout` 的合法 UTF-8 纯文本作为 `checkpoint` 摘要；退出码非 0 或输出为空时中止压缩并以退出码 `1` 退出。  
  * **内置默认压缩器（默认）**：使用 `[compact].provider` 与 `[compact].model`（未配置时回退当前会话的 `provider` 与 `model`），结合 `[compact].prompt` 或 `[compact].prompt_file`（二选一，未配置时回退内置极简摘要提示词）调用 Provider 生成摘要。  
  * 压缩器（无论内置或外部）均不具备 `msh` 工具权限，仅执行纯文本摘要。

### 6.2 无状态持久化上下文（`-c <file>`）与 WAL Schema

`/usr/bin/agent` 本体不维护中心化数据库；`-c <file>` 是唯一持久化原语，采用 **Append-Only JSONL（WAL）** 格式。

* **1\. 并发防线**：打开 `<file>` 时必须调用 `flock(LOCK_EX | LOCK_NB)` 获取独占非阻塞锁。若返回 `EWOULDBLOCK`，必须立即向 `fd 2` 报错并以退出码 `1` 退出。  
* **2\. KV-Cache 工程让步（不可变 Prefix \+ 尾部追加）**：

  *工程注记：在 Transformer 推理架构中，修改历史 Prefix 的任意字节都会导致整条 KV-Cache 失效与 TTFT 崩溃。因此本规范明确采用“首轮冻结 Prefix、后续变更一律尾部追加（Tail-Only Append）”的确定性契约。*

  * **首轮冻结**：新建 \&lt;file\&gt; 时，执行 `pre-context.d/` 并将初始配置写入 `session_init` 行，紧随其后将冻结的系统提示词写入 `turn_id: 0` 的 `role: "system"` 消息行；后续恢复时原样复用该冻结前缀。  
  * **Config Drift 尾部通知**：恢复运行若检测到契约类配置（如 `stderr`、`approval`）与 WAL 中最新生效状态不一致，当前调用参数胜出，严禁改动头部 `role: "system"`，仅在尾部追加一条 `runtime_update` 事件（映射至 IR 时作为尾部 `role: "system"` 增量消息，若上游 API 不支持中间 `system` 则由 Provider 降级为 `user`）。  
  * **大压缩分节（唯一刷新时机）**：仅当自动压缩、`aclr -s` 或 `SIGUSR1` 触发大压缩时，在文件末尾追加一个新的 **`checkpoint` 分节头**（携带 `ir_version: 1`、最新 `config` 与新 `turn_id`），紧接着追加重新执行 `pre-context.d/` 生成的新冻结 `role: "system"` 行与摘要行；`aclr -t` 尾部折叠严禁刷新头部 Prefix。  
* 3\. WAL JSONL 事件 Schema（每行必须为合法 JSON \+ \\n，每轮结束原子 flush；`role: "assistant"` 消息行可携带可选字段 `provider_opaque` 原样保存 Provider 返回的 `opaque.data` 以及可选字段 `usage`（同构 5 字段对象，见第 9.2 节；构造 Canonical IR 发给 Provider 时必须剥离，严禁写入 IR）；`checkpoint` 分节头可携带可选字段 `compact_usage`（仅内置压缩器生效时记录本次压缩消耗）与 `cumulative_usage`（5 字段前缀和，等于上一 `checkpoint` 的 `cumulative_usage`（无则为全 0）加上本段窗口内所有 `assistant.usage`（含后续被 `fold` 剪枝的行）与本次 `compact_usage`））：  
*

* **4\. 逆读回放算法与尾行损坏处理（Fail-Closed）**：  
  **逆读（Reverse-Read）到最新大压缩点**：启动加载 `-c &lt;file&gt;` 时，**必须从文件末尾（EOF）向前按行逆读**，避免扫描历史全量归档，使加载复杂度保持 O(当前活跃窗口)。  
  **尾行损坏处理（Fail-Closed）**：逆读首行（即文件最后一行）若非合法 UTF-8 JSON（如因 `SIGKILL` 或断电写半行），必须立即向 `fd 2` 报错并以退出码 `1` 退出，严禁静默丢弃数据。  
  **主动折叠自动剪枝（Single-Pass Reverse Fix）**：逆读过程中维护剪枝水位 `skip_ge = +∞`：  
  1\. 遇到 `fold` 事件（含 `from_turn` 与 `summary`）：将对应的 `&lt;folded turns="{from_turn}..{to_turn}"&gt;{summary}&lt;/folded&gt;` 压入结果栈，并更新 `skip_ge = min(skip_ge, from_turn)`。  
  2\. 遇到普通 `message` 或 `runtime_update`：凡扫描到的 `role: "assistant"` 行若携带 `usage`，**无论该行是否因 `turn_id >= skip_ge` 被 `fold` 剪枝，均必须累加计入当前窗口历史消耗**；若其 `turn_id &gt;= skip_ge`，**直接跳过丢弃**（自动消除死胡同探索及触发 `aclr -t` 的当轮孤立 `assistant(tool_call)`）；否则压入结果栈。  
  3\. 逆读完成剪枝检查时，若当前保留窗口的末尾（或 `skip_ge` 边界前一条）落在了带有未闭合 `tool_calls` 的 `assistant` 消息上，逆读器必须同样将其视为被折叠范围（继续上调 `skip_ge` 至该 `assistant.turn_id` 并丢弃之），确保重放结果 strictly 满足不变量 (2)。  
  4\. 遇到 `checkpoint` 或 `session_init` 分节头：校验其 `ir_version == 1`（不兼容则退出 `2`），提取最新生效配置后，叠加其 `cumulative_usage`，从而在严格保持 O(当前活跃窗口) 逆读复杂度的前提下获得精确的跨压缩会话总消耗 `session_usage`，随后**立即停止逆读**。  
  5\. 将收集到的消息列表 `reverse()` 反转，即得到按时间正序、无孤立 `tool_call` 的活跃上下文。

### 6.3 POSIX 信号处理规范

| 信号 | 确定性行为 |
| :---- | :---- |
| **`SIGINT`** | 向当前活跃子进程组（Provider / `msh`）发送 `SIGTERM`（等待 3 秒后仍未退出则 `SIGKILL`），丢弃未提交的半成品 Turn，释放 `flock`，以退出码 **`130`** 退出。 |
| **`SIGTERM`** | 执行与 `SIGINT` 相同的优雅清理流程，以退出码 **`143`**（`128 + 15`）退出。 |
| **`SIGSTOP`** / **`SIGCONT`** | 遵循内核默认行为，挂起与恢复进程。 |
| **`SIGUSR1`** | 置位原子标志；在下一轮 Provider 调用前强制触发一次全量压缩（等价于 `aclr -s`）。 |
| **`SIGUSR2`** | 将当前内存中的完整 Canonical IR JSONL 快照原子写入 `/tmp/agent_&lt;pid&gt;_&lt;epoch_ms&gt;.ctx.jsonl`（权限 `0600`），并在 `fd 2` 输出文件路径。 |

### 6.4 标准退出码表

| 退出码 | 含义 | 触发条件 |
| :---- | :---- | :---- |
| **`0`** | 成功 | 任务正常完成，Payload 已完整刷入 `fd 1`。 |
| **`1`** | 通用运行错误 | Provider 网络/协议失败、I/O 异常、`flock` 锁冲突、未知内部错误。 |
| **`2`** | 参数或语法错误 | CLI 参数非法、Frontmatter/`config.toml` 语法或未知字段错误、`ir_version` 不兼容（对齐 POSIX 及 Rust `clap`）。 |
| **`42`** | 权限/审批拦截 | 非交互环境下触发 `approval=ask` 拦截，或项目级 `hooks/` 未经 `agent trust` 校验/Hash 变更。 |
| **`124`** | 预算/超时熔断 | 达到 `max_turns`、超出 `max_tokens` 硬上限，或 Provider 调用超时（对齐 GNU `timeout(1)`）。注：单条 `msh` 子命令超时不终止 `agent` 进程，而是作为 `is_error=true` 工具结果返回模型。 |
| **`130`** | `SIGINT` 中断 | 收到 `SIGINT`（`128 + 2`）。 |
| **`143`** | `SIGTERM` 终止 | 收到 `SIGTERM`（`128 + 15`）。 |

## 7\. Model-oriented Shell (`msh`) 与 `a*` 工具集规范

### 7.1 `msh` 执行与过滤契约

调用方式：`msh -c "<command_string>"`（底层调用 `/bin/sh -c`，并在独立进程组 `setsid`/`setpgid` 中执行以确保信号可回收整棵子进程树）。

1. **1\. 防挂起环境变量注入**：强制注入 `NONINTERACTIVE=1`、`DEBIAN_FRONTEND=noninteractive`、`PAGER=cat`、`GIT_TERMINAL_PROMPT=0`、`TERM=dumb`、`NO_COLOR=1`。同时由 `agent` 将 `~/.local/libexec/agent/tools/` 前置注入 `msh` 默认 `PATH`，使 `a*` 工具集（`aview`、`aclr`）在 `msh` 会话内可直接调用。  
2. **2\. 二进制输出熔断（优先于文本清洗）**：检测合并捕获的输出流，若前 `8192` 字节包含 NUL（`0x00`）或整段流无法通过 UTF-8 校验：  
   * 严禁向模型输出乱码或擅自转多模态；  
   * 将原始字节写入 `/tmp/msh_<uuid>.bin`（权限 `0600`），基于文件头魔数探测 MIME（回退 `application/octet-stream`）；  
   * 仅返回单行元信息：`[binary output suppressed: <bytes>B, mime: <mime>, saved to /tmp/msh_<uuid>.bin. Use xxd/strings/pdftotext or aview to inspect]`。  
3. **3\. ANSI 清洗**：对合法 UTF-8 文本剥离所有 CSI / OSC 转义序列与覆盖式 `\r` 进度条。  
4. **4\. 超长输出折叠**：阈值默认为 `MSH_MAX_LINES=200` 或 `MSH_MAX_BYTES=8192`（可通过环境变量覆写）。超出任一阈值时，将清洗后的完整文本写入 `/tmp/msh_<uuid>.log`（权限 `0600`），仅返回 `exit_code`、前 20 行、省略行统计、后 20 行及完整日志路径。  
5. **5\. 单条命令超时与退出码透传**：默认命令超时为 `MSH_TIMEOUT_SEC=120`（可通过环境变量或 `config.toml` 覆写）。超时时 `msh` 必须向子进程组发送 `SIGTERM`（等待 3 秒后仍未退出则 `SIGKILL`），返回退出码 `124` 并附带超时提示。`agent` 收到 `msh` 退出码 `124` 时，严禁终止主进程，必须将该结果标记为 `is_error: true` 返回模型供其决策。

### 7.2 统一侧信道协议（`fd 6` / `$AGENT_CTL`）与 `a*` 工具

6. **绝不覆盖原生命令**：严禁覆写 `cat`、`ls`、`grep` 等系统命令，保证 `cat a.png | md5sum` 及 `.skills` 脚本 100% 保持原生字节流语义。  
7. **控制帧格式**：`a*` 工具通过环境变量 `AGENT_CTL`（`/dev/fd/6`）向主进程 `agent` 写入单行 JSONL 控制帧（单帧上限 64 KB）；`msh` 命令结束后，主进程按序读取并应用该次工具调用产生的所有控制帧：  
8. **多模态附加帧（`aview`）**：  
   * 

```
{"op":"media","mime":"image/png","path":"/tmp/aview_<uuid>.png","source":"screenshot.png"}
```

   * `aview` CLI 规范：`aview [--max-dim <px, 默认 1568>] [--pages <1-3,5>] [FILE | -]`。支持图片自动等比缩放与 PDF 指定页渲染为 PNG，结果落盘至 `/tmp/aview_<uuid>.png`（权限 `0600`）后向 `$AGENT_CTL` 写入上述控制帧。  
9. **上下文折叠帧（`aclr`）**：

```
{"op":"compact"}
{"op":"fold","from_turn":3,"summary":"使用xx是错误的"}
```

## 8\. 配置体系、目录解析与 `agent trust` 门禁

### 8.1 XDG 路径与向上查找规则

* **全局配置目录**：`$XDG_CONFIG_HOME/agent/`（未设置时回退 `~/.config/agent/`）。  
* **状态目录**：`$XDG_STATE_HOME/agent/`（未设置时回退 `~/.local/state/agent/`）。  
* **运行时目录**：`$XDG_RUNTIME_DIR/agent/`（未设置时回退 `/tmp/agent-<uid>/`，权限必须为 `0700`）。  
* **项目配置查找**：从 `cwd` 逐级向上查找 `.agent/` 目录，**遇到第一个 `.agent/` 即停止**；若向上到达 `.git` 所在目录（含该目录本身）或 `$HOME` 仍未找到则停止。

### 8.3 钩子覆盖与 `agent trust` 安全门禁

* **systemd 风格覆盖**：合并全局与项目 `hooks/&lt;stage&gt;.d/` 目录，按文件名 ASCII 字典序执行具备 `+x` 权限的文件；项目级同名文件覆盖全局；项目级同名空文件（0 字节）或指向 `/dev/null` 的软链用于屏蔽全局钩子。内置默认逻辑 `00-posix-runtime`、`20-skills` 与 `30-tips` 作为最低优先级内置钩子生效，可被全局或已信任项目 `hooks/pre-context.d/` 下的同名文件覆盖，或通过 0 字节文件 / 指向 `/dev/null` 的软链屏蔽。  
* **防 RCE 强校验**：项目级 `config.toml` 默认生效；但项目级 `hooks/` 下的任何可执行脚本默认**严禁执行**。若项目级 `.agent/config.toml` 中配置了 `[compact].bin`（或自定义 `providers.&lt;name&gt;.bin`），同样属于项目级外部代码执行，必须纳入 `agent trust` 校验范围。用户必须显式运行 `agent trust &lt;project_dir&gt;`，将每个钩子脚本及自定义可执行文件的规范绝对路径（`realpath`）与内容 SHA-256 摘要写入 `$XDG_STATE_HOME/agent/trusted.json`。

```
{"version":1,"hooks":{"/abs/path/.agent/hooks/pre-context.d/10-custom":{"sha256":"<hex>","trusted_at":"2026-11-24T12:00:00Z"}}}
```

运行时若检测到未信任的项目钩子或文件 SHA-256 发生变更，必须立即中止执行、向 `fd 2` 输出未信任路径并以退出码 **`42`** 退出。

## 9\. Canonical IR 与外部插件线协议（`ir_version = 1`）

所有外部插件（Provider 与 Hooks）均为语言无关的可执行进程，通过 `stdin`/`stdout` 交换 UTF-8 JSON 数据。

### 9.1 Canonical IR v1 规范（`ir_version = 1`，JSONL）

Canonical IR 是 `agent` 核心与外部 Provider、`pre-context.d/` 钩子及外部压缩器（`[compact].bin`）之间交换的唯一标准推理请求格式。为与 WAL、Provider 输出及 Trace 保持 100% 协议同构并最大化 `jq` / Shell 管道友好性，**Canonical IR 采用严格 UTF-8 JSONL（每行一条独立 JSON 对象 \+ \\n）**。

* **不绑定模型**：IR 中严禁包含 `model` 字段；目标模型统一由运行时通过环境变量 `AGENT_MODEL` 注入给 Provider，确保同一份 IR 流可零修改重放至任意模型或压缩器。  
  **所有角色扁平化**：统一采用扁平 `text` 字段 \+ 可选 `media[]` 附件数组，严禁嵌套 `ContentPart[]`；系统提示词不再单设顶层字段，统一表示为 `role: "system"` 消息行。  
* **第 1 行：流头（`type = "header"`，必填且仅出现一次）**：  
  `ir_version` (`uint32`, 必填)：必须为 `1`；Provider 遇到不支持版本必须向 `stderr` 报错并以退出码 `2` 退出。  
  `type` (`"header"`, 必填)：固定字面量。  
  `tools` (`ToolDef[]`, 必填)：工具声明数组（全量压缩时为 `[]`，为空时 Provider 必须省略上游工具字段）。  
  `max_output_tokens` (`uint32`, 可选)：单轮输出 Token 上限（未设置或为 `0` 时省略）。当该字段存在时，Provider **必须**将其映射至上游 API 的对应输出上限参数（如 OpenAI Responses 的 `max_output_tokens`、Anthropic 的 `max_tokens`），严禁静默忽略。  
  `params` (`object`, 可选)：经运行时浅合并后的模型透传参数字典（为空时省略），由 Provider 自行解释与映射。推荐生态对齐键：`reasoning_effort`（`"none"|"low"|"medium"|"high"`）、`temperature`（`float`）；Provider 遇到自身不支持的键时**应当**忽略或向 `stderr` 输出非致命警告，严禁因此失败退出。  
  `meta` (`Meta`, 必填)：`{"stderr_mode": "auto"|"explicit", "cwd": "<abs_path>"}`，可选含 `turn_budget`。  
  *前向兼容*：`ir_version = 1` 下遇到未识别扩展字段（如 `x_*`）必须忽略而非报错；钩子应当原样透传未修改字段。  
* **第 2..N 行：消息流（按 `role` 区分，顺序即时间顺序）**：  
* **`role = "system"`**：`turn_id` (`uint64`, 必填)、`text` (`string`, 必填)。首条 `role: "system"` 为冻结系统前缀，Provider 必须映射至上游 `system` / `instructions` 且严禁改动其字节内容以保 KV-Cache；尾部因 `runtime_update` 追加的 `role: "system"` 若上游 API 不支持中间 `system` 角色，由 Provider 降级映射为 `user` 消息。  
  * **`role = "user"`**：`turn_id` (`uint64`, 必填)、`text` (`string`, 必填)、`media` (`MediaAttachment[]`, 可选，无附件时省略)。  
  * **`role = "assistant"`**：`turn_id` (`uint64`, 必填)、`text` (`string`, 可选)、`reasoning` (`string`, 可选，不支持回传思考链的 Provider 可忽略)、`tool_calls` (`ToolCall[]`, 可选，每项含 `id`、`name`、`arguments` JSON 对象；`text` 与 `tool_calls` 不可同时为空)、`provider_opaque` (`object`, 可选，用于透传加密思维链或签名等 Provider 私有字段，跨 Provider 切换时必须清空)。  
  * **`role = "tool"`**：`turn_id` (`uint64`, 必填)、`tool_call_id` (`string`, 必填，精确匹配紧邻前序 `assistant.tool_calls[].id`)、`is_error` (`bool`, 可选，默认 `false`)、`text` (`string`, 必填)、`media` (`MediaAttachment[]`, 可选，承载 `aview` 产生的本地图片附件)。  
* **多模态附件（`MediaAttachment`）**：  
  * 结构：`{"mime": "<mime>", "path": "<abs_path>"}`。`mime` 仅允许 `image/png`、`image/jpeg`、`image/webp`、`image/gif`（PDF 由 `aview` 渲染为 PNG 后复用）。  
  * **延迟读盘契约**：`agent` 严禁将 Base64 写入 IR 或 WAL；由 Provider 在发起 HTTP 请求前按 `path` 读盘编码。文件不存在或不可读时，Provider 必须输出 `{"type":"error","code":"media_not_found","retryable":false}` 并以退出码 `1` 退出。  
* **WAL 特殊事件归一化映射**：  
  * `checkpoint`：作为逆读分节终点，以该节紧随其后的新冻结 `role: "system"` 消息作为首条系统前缀，并将摘要行作为随后的 `role: "user"` 消息注入：`&lt;checkpoint&gt;\n{summary}\n&lt;/checkpoint&gt;`。  
  * `fold`：弹出 `turn_id &gt;= from_turn`（经工具对闭合对齐后）的全部消息（含触发 `aclr -t` 的当轮 `assistant`），原位压入一条 `role: "user"` 文本：`&lt;folded turns="{from_turn}..{to_turn}"&gt;{summary}&lt;/folded&gt;`。  
  * `runtime_update`：严禁改动首条冻结 `role: "system"` 消息；在漂移处注入一条尾部 `role: "system"` 增量消息（文本为 `&lt;runtime_update&gt;{content}&lt;/runtime_update&gt;`；若上游 API 不支持中间 `system` 角色，由 Provider 降级映射为 `role: "user"`）。  
* **发送前结构不变量**：(1) 首行必为 `header` 且后续至少包含一条非 `header` 消息；(2) `assistant.tool_calls[].id` 必须在紧随其后的连续 `tool` 消息中一一配对，严禁孤立或穿插其他角色；(3) 除同一 `checkpoint` 分节内冻结 `system` 与首条摘要可共享起始锚点外，`turn_id` 整体非降序且对话轮次严格单调递增。

示例：

```json

{"ir_version":1,"type":"header","tools":[{"name":"msh","description":"Execute a non-interactive shell command. Redirect final deliverables to $AGENT_OUT and human-facing messages to $AGENT_ERR.","parameters":{"type":"object","properties":{"cmd":{"type":"string"}},"required":["cmd"]}}],"max_output_tokens":16384,"params":{"reasoning_effort":"high"},"meta":{"stderr_mode":"auto","cwd":"/abs/path/to/repo"}}
{"turn_id":0,"role":"system","text":"<posix_runtime>...</posix_runtime>\n\n你是一个安全审计专家..."}
{"turn_id":1,"role":"user","text":"分析这个报错截图"}
{"turn_id":2,"role":"assistant","reasoning":"...","text":"","tool_calls":[{"id":"call_1","name":"msh","arguments":{"cmd":"aview err.png"}}]}  
{"turn_id":3,"role":"tool","tool_call_id":"call_1","text":"[t3] exit=0\n","media":[{"mime":"image/png","path":"/tmp/aview_xxx.png"}]}
```

### 9.2 Provider Adapter 线协议（`git-remote-*` 模式）

* **注入环境变量**：`AGENT_PROVIDER_BASE_URL`、`AGENT_PROVIDER_API_KEY`（由 `agent` 优先从 `api_key_env` 指定的环境变量解析，非空时生效；若环境变量未设置或为空，则回退至配置中的 `api_key`）、`AGENT_PROVIDER_TIMEOUT_SEC`、`AGENT_MODEL`。  
* **输入（`stdin`）**：Canonical IR JSONL 流（首行为 header，后续每行一条消息），写完即关闭写端（EOF）。  
* **输出（`stdout`）**：每行一条标准 JSONL 事件，必须支持以下事件类型：  
*   
* 

```
{"type":"reasoning_delta","text":"..."}
{"type":"text_delta","text":"..."}
{"type":"tool_call","id":"call_1","name":"msh","arguments":{"cmd":"..."}}

{"type":"usage","input_tokens":4200,"output_tokens":380,"cached_tokens":3600,"cache_write_tokens":400,"reasoning_tokens":200}
{"type":"opaque","data":{...}}
{"type":"error","code":"rate_limit","message":"429 Too Many Requests","retryable":true}
{"type":"done","finish_reason":"tool_calls"}
```

* **usage 包含式口径契约**：  
  1\. 统一 5 字段结构贯穿 Provider 事件、WAL（`assistant.usage` / `checkpoint.compact_usage` / `checkpoint.cumulative_usage`）、`fd 3` Trace 与 `on-exit.d/`，严禁写入第 9.1 节 Canonical IR 请求流。  
  2\. `input_tokens`（uint64, 必填）必须采用**包含式（Inclusive）**总输入口径，包含 `cached_tokens` 与 `cache_write_tokens`（若上游 API 如 Anthropic 默认不含缓存读写，Provider 必须在输出前归一化累加）；`output_tokens`（uint64, 必填）必须采用包含式总输出口径，包含 `reasoning_tokens`。  
  3\. `cached_tokens`、`cache_write_tokens`、`reasoning_tokens`（uint64, 可选）在上游未提供时可省略，内核与累加器均按 `0` 处理。  
  4\. 单次进程内的运行累计消耗（`run_usage`）必须包含本次运行中所有 Provider 调用（含大压缩内置压缩器调用）。  
* `opaque` 事件用于透传 Provider 私有不透明状态（如加密思维链或签名）；若本轮收到 `opaque` 事件，`agent` 必须将其 `data` 持久化写入该轮 `role: "assistant"` 的 `provider_opaque` 字段，并在后续调用同一 Provider 时原样回传（跨 Provider 切换时清空）。  
  **重试归属契约**：Provider 驱动必须保持无状态单次请求，严禁在内部自行隐式重试；遇到上游限流（429）或临时服务端错误（5xx）时，输出 `{"type":"error","code":"...","message":"...","retryable":true}` 并以非零退出。由主进程 `agent` 统一执行指数退避重试（默认最多重试 3 次，退避间隔 1s / 2s / 4s，每次失败均落盘 `provider_error` Trace 事件）；重试耗尽仍失败时向 `fd 2` 报错并以退出码 `1` 退出。  
* **错误与退出码**：Provider 进程非零退出或未输出 `done` 即关闭 `stdout` 时，`agent` 必须向 `fd 2` 输出 Provider 的 `stderr` 并以退出码 `1`（超时为 `124`）退出。

### 9.3 Lifecycle Hooks 线协议（`run-parts` 模式）

* **`pre-context.d/`**：`stdin` 接收 Canonical IR JSONL 流，`stdout` 输出修改后的 Canonical IR JSONL 流（钩子可直接追加或改写 role: "system" / 其他消息行）。退出码 `0` 表示继续，非零退出则中止整个 `agent` 进程（透传报错至 `fd 2` 并退出 `1`）。  
* **`post-tool.d/`**：`stdin` 接收 `{"turn_id":3,"tool_call_id":"call_1","cmd":"...","exit_code":0,"output":"..."}`，`stdout` 输出修改/脱敏后的同构 JSON；非零退出中止执行。  
* **`on-exit.d/`**：进程退出前触发，`stdin` 接收 `{"exit_code":0,"turns":4,"usage":{...},"session_usage":{...},"context":{"tokens":42100,"max_tokens":128000},"context_file":"..."}`（其中 `usage` 为本次运行累计 5 字段消耗，`session_usage` 为跨压缩会话总累计 5 字段消耗（无状态运行时等于 `usage`），`context` 为退出时的最终上下文水位），单钩子默认超时 `5s`，失败仅记录至 Trace 不覆盖主进程退出码。

### 9.4 `.skills` 渐进式披露钩子（`20-skills`）

1. `20-skills` 默认逻辑内置于 `agent` 二进制中（无需磁盘预置脚本即可生效），可按第 8.3 节规则被外部同名文件覆盖或屏蔽。  
   **扫描顺序（高优先同名覆盖低优先）**：  
   `./.agent/skills/` → `./.skills/` → `./.claude/skills/` → `~/.config/agent/skills/` → `~/.skills/` → `~/.claude/skills/`。  
2. **索引提取**：仅解析 `&lt;skill_dir&gt;/SKILL.md` 的 YAML Frontmatter 中必需字段 `name` 与 `description`，按确定性 XML 格式追加至首条 `role: "system"` 消息文本末尾：

```
<available_skills>
  <skill name="pdf-extract" path="/abs/path/SKILL.md">Extract tables from PDFs</skill>
</available_skills>
```

3. **按需加载**：模型需要某项技能时通过 `msh` 执行 `cat /abs/path/SKILL.md` 读取完整说明。

### 9.5 结构化 Trace 线协议（`fd 3` / `journal.sock`）

4. **按需激活与非阻塞铁律**：Trace 默认不写入任何磁盘或 Socket；仅当 `fd 3` 已打开可写或 `$XDG_RUNTIME_DIR/agent/journal.sock`（Unix Domain `SOCK_STREAM`）存在时激活。写入遇到 `EPIPE` 或对端关闭时必须静默关闭 Trace 写端，**严禁阻塞推理循环或影响主进程退出码**；严禁将 `AGENT_PROVIDER_API_KEY` 等密钥写入 Trace。  
5. **公共信封字段**（单行 UTF-8 JSONL，支持父子 Agent 嵌套溯源）：

   `{"v":1,"ts":"2026-11-24T13:30:00.123Z","pid":48210,"ppid":48102,"agent":"security-auditor","type":"..."}`

6. **三级存储粒度（`AGENT_TRACE_LEVEL`）**：  
   * `events`（`journal.sock` 推荐默认）：记录完整生命周期事件（`run_start`、`llm_request_start`、`llm_response`、`provider_error`、`tool_approval`、`tool_start`、`tool_end`、`compact`、`fold`、`warning`、`error`、`run_end`）；其中 `llm_response` 携带当轮 5 字段 `usage`，`run_end` 携带 `usage`、`session_usage` 与 `context` 水位对象。发生网络断连或重试时，`provider_error` 必须立刻落盘并附带 `code`、`attempt`、`elapsed_ms`、`provider_stderr` 及断连前已收到的 `partial_text`/`partial_reasoning` 与 `last_delta_ts`，确保无需开启 `deltas` 即可定位流式中断。  
   * `deltas`（显式 `3&gt; file` 推荐默认）：在 `events` 基础上追加每一帧流式 `reasoning_delta` / `text_delta`，适用于 `tail -f` 实时观测与流式卡顿排查。  
   * `wire`（显式排障开启）：额外落盘完整 Canonical IR 输入、Provider 原始输出帧与未清洗的 `msh` 原始输出；**严禁发往共享的 `journal.sock`**，仅允许写入权限为 `0600` 的独立排障文件。

### 9.6 内置 `30-tips` 钩子（渐进式运行时手册）

为避免在核心运行时中硬编码 `/loop`、`/goal`、多 Agent 编排等上层策略，同时确保模型在需要时知晓如何组合 POSIX 原语，`agent` 内置优先级为 `30` 的默认上下文钩子 `30-tips`。

* **零元数据索引**：`tips` 目录下的文件**不要求**任何 YAML Frontmatter 或特定结构，**文件名本身即索引**（推荐采用 `how-to-<topic>.md` 命名，如 `how-to-loop.md`、`how-to-goal.md`、`how-to-sub-agent.md`）。  
* **三层来源与同名覆写/单篇屏蔽**（低优先级被高优先级同名文件覆盖）：  
  1\. 内置默认层（最低优先级）：`agent` 二进制内置默认指南（如 `how-to-goal.md`、`how-to-loop.md`、`how-to-sub-agent.md`），首次执行 `30-tips` 时自动原子释放至 `${XDG_STATE_HOME:-$HOME/.local/state}/agent/builtin-tips/`（只读目录不可写时回退至 `$XDG_RUNTIME_DIR/agent/builtin-tips/`），确保单二进制零预置文件开箱即用，且随版本升级自动刷新、不污染用户配置目录。  
  2\. 全局目录：`${XDG_CONFIG_HOME:-$HOME/.config}/agent/tips/`  
  3\. 项目目录：`<cwd>/.agent/tips/`  
  扫描扩展名为 `.md` 的常规文件（忽略隐藏文件与子目录）。高优先级目录的同名 `.md` 覆盖低优先级条目；高优先级目录中放置**同名 0 字节文件或指向 `/dev/null` 的符号链接**可单独屏蔽该篇 tip（含内置默认 tip）。合并后若条目为空，静默跳过（零 Token 开销）。  
* **输出格式（绝对路径）**：收集去重后按文件名 ASCII 字典序排列，向系统提示词注入紧凑的 `<runtime_tips>` 索引块，每行输出文件的**规范化绝对路径**（避免子进程切换工作目录后相对路径失效）：  
* 

```xml
<runtime_tips>
For advanced POSIX workflows, read the relevant guide via msh when needed:
/home/user/.local/state/agent/builtin-tips/how-to-goal.md
/home/user/.local/state/agent/builtin-tips/how-to-loop.md
/home/user/.local/state/agent/builtin-tips/how-to-sub-agent.md
</runtime_tips>
```

* **整块覆写与禁用**：与 `20-skills` 遵循完全相同的 `run-parts` 覆盖规则——用户或项目在 `pre-context.d/` 下放置同名可执行文件 `30-tips` 即可覆写其行为；放置 0 字节文件或指向 `/dev/null` 的符号链接即可彻底禁用整块 `30-tips`（不释放内置文件，零 Token 开销）。

## 10\. 运行环境、内核适配与分发安装

### 10.1 容器底座建议

* **默认主力**：Debian Slim（\~22 MB），提供原生 glibc 与完整 GNU Coreutils。  
* **动态工具链环境**：Ubuntu Minimal（\~30–75 MB）。  
* **高密微沙盒**：Alpine Linux（\~5–8 MB），仅推荐工具集完全静态化场景。

### 10.2 Linux 内核特性优雅降级

* **全平台基础模式**：纯 POSIX，完整支持 Linux、macOS、WSL2。  
* **Linux ≥ 5.13 强化模式**：启动时自动探测内核能力：  
  * **进程树回收（pidfd / PR\_SET\_PDEATHSIG）**：确保主进程异常终止时内核可靠回收所有子进程（Provider / `msh`），杜绝孤儿进程持续消耗资源。  
  * **Landlock LSM（可选开启，通过 \--sandbox 或 \[sandbox\].enabled \= true）**：默认限制 `msh` 子进程仅对 `$PWD`、`/tmp` 与 `$XDG_RUNTIME_DIR` 具备写权限，其余系统路径只读；内核不支持时打印警告并降级（若传 `--sandbox=strict` 则直接以退出码 `1` Fail-Closed 退出）。

### 10.3 安装脚本与自检（`agent --doctor`）

单行零 root 安装：`curl -fsSL https://get.os-agent.dev | sh`（将 `agent` 安装至 `~/.local/bin/`、`msh` 与默认 Provider 安装至 `~/.local/libexec/agent/`、`a*` 工具集安装至 `~/.local/libexec/agent/tools/`，初始化全局配置与默认钩子、不修改用户 shell rc 文件）。  
agent \--doctor 必须按序执行以下确定性检查，全部通过返回 0，任一项失败返回 1 并指明修复命令：

1. 1\. 校验 `~/.local/bin/agent`、`~/.local/libexec/agent/`（`msh` 及默认 Provider）与 `~/.local/libexec/agent/tools/`（`aview`、`aclr`）二进制存在且具备 `+x` 权限。  
2. 2\. 校验全局/项目 `config.toml` 语法合法，且默认 Provider 的密钥配置就绪（`api_key_env` 对应环境变量非空或 `api_key` 非空；若两者均显式为空则视作免鉴权端点放行）。  
3. 3\. 校验 `/dev/fd` 挂载可用且匿名管道转发正常。  
4. 4\. 校验 `$XDG_RUNTIME_DIR` 权限与 `flock` 文件锁可用性。

## 11\. 生态系统与未来扩展（Non-Normative）：agent-sh

`agent-sh` 不属于 OS Agent v1.0 核心发行包，而是规划在外部生态系统中的未来独立项目（Non-Normative 参考设计）。它作为位于 `agent` 上层的 PTY 旁路包装器，通过完全复用本规范定义的 POSIX 原语，在保留原生 Zsh/Bash 体验的同时无缝调度默认 Agent（如 `bash.agent`）。

### 11.1 架构定位与 OSC 133 环形缓冲区

* **零侵入包装**：通过 PTY 启动用户默认 `$SHELL`，100% 保留 `.zshrc`/`.bashrc`、alias、补全与全屏 TUI 程序（`vim`/`htop`）；本体严禁内置 LLM SDK。  
* **OSC 133 语义捕获**：向底层 Shell 注入极简 OSC 133 钩子：  
  * `\x1b]133;A\x07`（Prompt 开始）、`\x1b]133;B\x07`（用户输入开始）、`\x1b]133;C\x07`（命令开始执行）、`\x1b]133;D;<exit_code>\x07`（命令执行结束）。  
* **环形缓冲区默认值**：内存保留最近 `AGENT_SH_HISTORY_SIZE=10` 条命令记录（字段：`cwd`、`cmd`、`exit_code`、经 `msh` 同款规则清洗且截断至 `4096` 字节的 `output`）。

### 11.2 确定性输入路由顺序

用户输入回车后，`agent-sh` 必须严格按以下顺序判定路由：

1. **1\. 空白输入**：直接透传原生 Shell。  
2. **2\. 显式前缀**：以 `?`  或 `#` 开头时，剥离前缀并直接路由至默认 Agent。  
3. **3\. 合法 Shell 命令**：检查首词是否为底层 Shell 的 builtin、alias、函数、`$PATH` 可执行文件或有效路径（`./`、`/`）；命中则以 0ms 延迟交由原生 Shell 执行。  
4. **4\. 自然语言回退**：包含非 ASCII 字符或首词未命中上述列表时，拦截并路由至默认 Agent。

### 11.3 与 `agent` 核心原语对接

* **会话持久化**：每个终端实例分配 `/tmp/agent-sh-<sid>.ctx.jsonl`（权限 `0600`），通过 `-c` 维护多轮上下文，退出时自动清理。  
* 

```sh
echo "分析一下上一条是什么？" | bash.agent -c /tmp/agent-sh-<sid>.ctx.jsonl 4< <(recent_shell_history)
```

* 安全回填父 Shell：bash.agent 需要变更父 Shell 状态（如 cd/export）时，将命令写入 \$AGENT\_OUT（fd 1）；agent-sh 读取后将其预填至原生 Shell 输入缓冲区（等价于 Zsh print \-z），由人类审阅后按回车执行。
